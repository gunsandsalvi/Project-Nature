# B73: adding the writer test to the phone test app

`phone/WriterTest.kt` runs the 20 sample prompts (10 records, 2 voices) through Gemini Nano, the phone's built-in model, with ML Kit's GenAI Prompt API (`PRE-37`). For each prompt it reports the time to the first word, words per second, the text and any error. It also reports whether the model was ready or still downloading, its name, and heat and free memory before and after (`RSK-22`). It is one file with the prompts inside, generated by `make_prompts.py` from the same data as the cloud run.

## Steps

1. Copy `phone/WriterTest.kt` to `app/app/src/main/java/dev/kindling/pretests/`. Its package is `dev.kindling.pretests`.
2. In `app/app/build.gradle.kts`, under `dependencies`:
   `implementation("com.google.mlkit:genai-prompt:1.0.0-beta4")`
3. In `app/gradle.properties`, set `android.useAndroidX=true`. **This is required**: ML Kit brings in AndroidX (appcompat 1.6.1, core 1.9.0, fragment 1.3.6). With it off, the build stops at `checkDebugAarMetadata`, as the compile check showed.
4. Optional: add these to the app's manifest, so the result can name the Play services and Private Compute Services versions. Without them, those two fields say "not found". AICore's own version needs nothing, because ML Kit's manifest already declares it.
   ```xml
   <queries>
       <package android:name="com.google.android.gms" />
       <package android:name="com.google.android.as.oss" />
   </queries>
   ```
5. Call it from a worker thread, with the app on screen and the screen kept on:
   ```kotlin
   window.addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)
   Thread {
       val b73 = WriterTest.run(applicationContext)        // blocks; at most about 4.5 minutes
       runOnUiThread { result.put("b73", b73) }           // then show the result code as usual
   }.start()
   ```
   Never call it on the main thread. ML Kit only writes while the app is the top app on screen. If the owner switches away, the run stops with `BACKGROUND_USE_BLOCKED`, and the result says so.
6. Put the returned JSON under `"b73"` in the result code. The texts must come back, because the fact checker runs on them in the cloud: `python check_texts.py <file with the b73 object>`. The object is about 15 to 30 KB, so compress it with the rest of the result.

## How long it runs

- **Default budget: 270 s** (`WriterTest.run(context, budgetMs)`). It never starts a prompt with less than 15 s left, and each prompt is cut off at 60 s. The whole run stays under 5 minutes.
- **Model already on the phone:** the FULL pass is 20 prompts at roughly 5 to 15 s each, so about 2 to 4 minutes. The FAST pass (the lighter variant, if the phone has it) only uses time left over, and is skipped if less than 60 s remain.
- **Model not yet downloaded:** it starts the download, waits up to 90 s, and reports the size and progress (`status: downloadable` or `downloading`). Run the test again later, with the phone on Wi-Fi.

## Requirements

- **Android:** API 26 or later for the library; the app's minSdk is 31. Tested here: compileSdk 36, AGP 8.13.2, Kotlin 2.3.21, debug and minified release builds (see NOTES.md).
- **Phone:** Gemini Nano through the Prompt API. Google lists the Pixel 11 series as Gemini Nano v4, and the Pixel 9 and 10 as v3 (checked 1 October 2026).
- **System apps:** Android AICore installed and up to date, plus Private Compute Services and Google Play services up to date (update them from the Play Store before the run).
- **Locked bootloader:** the API refuses phones with an unlocked bootloader.
- **Limits:** input under 4,000 tokens (our longest prompt is 1,815 characters, about 450 tokens). Each app has quotas: too many requests in a short time give `BUSY`, and a long-term battery quota gives `PER_APP_BATTERY_USE_QUOTA_EXCEEDED`. The test records either and stops.

## What comes back

```text
b73: version, api, device {model, soc, android, sdk, aicore, play_services, ...},
     before / after {battery_c, thermal, headroom_10s, avail_mem_mb},
     passes: [ {preference: FULL | FAST, status, base_model, token_limit, warmup_ms,
                runs: [ {id, voice, dark, ttfw_ms, total_ms, words, wps, wps_all, finish, text,
                         battery_c, thermal, error_code?} ], summary {...}} ]
```

`wps` is words a second after the first word; `wps_all` includes the wait for it. Settings match the cloud run: temperature 0.3, top-k 20, seed 73, at most 256 new tokens.

## The owner's part

After the run, the owner reads 6 texts and rates each as poor, acceptable or good (decision rule 6): records `r04` (the feud killing), `r06` (the dream) and `r08` (the sky-fire sign), in both voices. The lead can paste them into the report from the result.
